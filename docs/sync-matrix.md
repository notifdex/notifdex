# Cross-Platform Sync Coverage Matrix (macOS ↔ iOS)

This document audits all Notifdex data categories across macOS and iOS, specifying what synchronizes through the opt-in private CloudKit zone (`iCloud.com.notifdex.shared` / `NotifdexSyncZone`), what remains device-local by design, and how concurrent edits and deletions are resolved deterministically.

## Source of Truth & Architecture

- **Single shared core:** Both macOS (`capture.db`) and iOS (`notifdex-core.db`) run `NotifdexCore.CaptureStore` (SQLite schema v13) and `HybridSyncCoordinator`.
- **Opt-in & device-scoped:** Sync is **Local-Only** by default (`UnpairedOrRevokedNeverSyncs`). Enabling sync pairs the device in `sync_devices`; revoking a device stops future pushes/pulls and clears stale sync cursor metadata while preserving 100% of local data.
- **Privacy invariant:** Locally hidden alerts on Mac never have their content (`SyncedObservationRecord`) uploaded to CloudKit (`HiddenNeverLeaksToCloudOrIPhone`). When an already-visible/dual-captured alert is later hidden or restored on either device, only an opaque `SyncedHiddenAlertRecord` (keyed by `syncUUID` + `logicalKey` hash, containing zero notification text) propagates the hide/restore state to devices that already hold that alert.
- **Offline queue & retries:** Every local mutation commits durably to SQLite first and triggers `AutoSyncEngine` (single-flight debounce + exponential backoff on transient failures, plus CloudKit silent push wake and foreground/periodic pulls). Pushing is digest-deduplicated and idempotent; applying remote batches is transactional and safe to replay.

## Coverage Matrix

| Data Category | Storage Table / File | Pre-#111 Status | Current Status | Conflict Resolution & Deletion Semantics |
| --- | --- | --- | --- | --- |
| **Notification records & provenance** | `observations`, `sync_observation_links` | Synchronized | **Synchronized** | Immutable content keyed by `sync_uuid` + `(source_id, source_event_id, …)`. Cross-device duplicates collapse visually via `logical_key` without deleting raw evidence. Locally hidden alerts are never uploaded. Respects device-local `local_pruned_before` storage cleanup watermark. |
| **Read/unread (dimmed), flagged, saved, follow-ups, person link, alert workspace** | `read_observations`, `flagged_observations`, `observation_work`, `person_observations`, `observation_workspaces` | Partially synchronized (macOS unlinked edits & `markOpened` missed bumps; alert workspaces unsynced) | **Synchronized** | Monotonic per-observation `workflow_version` LWW (tie-break by newer `updated_at`), propagated across cross-device twins. `CaptureStore` atomically ensures sync links and bumps versions for all mutations on both macOS and iOS. |
| **Individual alert hide / restore** | `hidden_observations`, `sync_observation_links.hidden_version` | Not synchronized | **Synchronized (privacy-preserving)** | `SyncedHiddenAlertRecord` carries only `(syncUUID, logicalKey, isHidden, hiddenVersion, hiddenUpdatedAt)` — zero alert text. Higher `(hiddenVersion, hiddenUpdatedAt)` wins; equal timestamp tie-breaks conservatively toward hidden (`isHidden = true`) so hidden alerts are not unexpectedly revealed. |
| **Notification hide rules (app, title, body/subject)** | `inbox_filters` (`field IN ('app', 'title', 'body')`, `enabled`, `updated_at`) | Not synchronized (no app-level scope, no timestamps/tombstones) | **Synchronized** | Canonical deterministic key `(app, field, value)` prevents duplicates across devices. LWW by `updated_at` (equal-timestamp tie-break favors `enabled = true`). Removals write timestamped `inbox_filter` tombstones (`deleted_at >= updated_at` suppresses stale re-adds; a strictly newer re-create/undo `updated_at > deleted_at` supersedes the tombstone). |
| **People (contacts)** | `people` | Partially synchronized (no delete tombstone or `updated_at`) | **Synchronized** | Upsert by stable UUID with LWW `updated_at` on `display_name`; `deletePerson` records `person` tombstone atomically in `CaptureStore`. |
| **Person identities (handles / emails)** | `identities` | Not synchronized | **Synchronized** | Keyed by stable UUID + `(platform, identifier)` uniqueness guard; `removeIdentity` records `identity` tombstone atomically in `CaptureStore`. |
| **Person auto-match rules & exclusions** | `person_match_rules`, `person_match_exclusions` | Not synchronized | **Synchronized** | Keyed by stable rule UUID + `(app, title)` uniqueness; `removePersonMatchRule` records `person_match_rule` tombstone. Exclusions follow explicit unlinks via `SyncedWorkflowRecord`. |
| **Personal notes & folders** | `personal_notes`, `note_folders` | Partially synchronized (macOS deletes lacked tombstones; folders lacked tombstones) | **Synchronized** | Notes resolve via LWW `updated_at`; `deletePersonalNote` and `deleteNoteFolder` record tombstones (`personal_note`, `note_folder`) atomically in `CaptureStore`. Folder deletion preserves notes as Unfiled (`ON DELETE SET NULL`). |
| **People notes** | `person_notes` | Partially synchronized (macOS deletes lacked tombstones) | **Synchronized** | Notes resolve via LWW `updated_at`; `deletePersonNote` records `person_note` tombstone atomically in `CaptureStore`. |
| **Workspaces & memberships** | `workspaces`, `person_workspaces`, `observation_workspaces` | Not synchronized | **Synchronized** | Workspaces sync by stable UUID (`name` case-insensitive unique). Person memberships sync with LWW `(is_member, updated_at)` so add/remove propagates cleanly. Alert routing syncs in `SyncedWorkflowRecord.workspaceID`. |
| **Relationship templates & outreach stages** | `relationship_templates`, `person_templates`, `person_template_milestones` | Not synchronized | **Synchronized** | Versioned template definitions install idempotently; per-person assignment, stage, and milestone progress resolve via LWW `updated_at`; removals record `person_template` tombstones. |
| **Shared user preferences** | `sync_state` (`pref_color_theme`, `pref_group_by_app`, `pref_updated_at`) | Not synchronized | **Synchronized** | LWW by `updated_at` for cross-platform preferences (accent pigment theme, inbox app grouping preference). |
| **Capture configuration & runtime state** | macOS `settings.json` (`sourceID`, `paused`, `automaticRecovery`, enabled Accessibility apps); iOS `ios-capture.db` (`CaptureSettingsState`, `verifiedAppLabels`, `intent_execution_logs`) | Device-local by design | **Device-local by design** | Capture mechanisms differ by OS (macOS Accessibility vs. iOS 27 Shortcuts automations). Each device independently controls capture pause, recovery, and which apps it collects. |
| **Platform UI & window layout** | macOS `AppearanceSettings` (`surfaceMode`, `glassTintStrength`, `custom-backdrop.img`, `menuBarIconStyle`), NSWindow frame, split divider width; transient search/tab state | Device-local by design | **Device-local by design** | Desktop glass finishes, custom wallpaper files, menu bar icons, and window geometry are platform-specific and intentionally stay local. |
| **Sync pairing, cursors & local retention watermark** | `sync_state` (`sync_enabled`, `auto_sync_enabled`, `local_device_id`, `sync_change_token`, `sync_last_pushed_digest`, `local_pruned_before`), `sync_devices` | Device-local by design | **Device-local by design** | Pairing consent, CloudKit server tokens, and per-device storage cleanup watermarks remain strictly local to each device. |

## Formal Verification

- [`spec/HybridSync.tla`](../spec/HybridSync.tla): Verifies opt-in pairing, revocation isolation, hidden-content non-leakage, cross-device dual-capture collapse, and forwarding health soundness.
- [`spec/AutoSync.tla`](../spec/AutoSync.tla): Verifies single-flight execution, debounce coalescing, bounded exponential backoff, and mid-sync trigger preservation.
- [`spec/FilterSync.tla`](../spec/FilterSync.tla): Verifies deterministic cross-device hide-rule and preference convergence across concurrent edits, deletions, re-creations (undo), offline retries, duplicate delivery, conservative tie-breaking, and device-local preference isolation.
